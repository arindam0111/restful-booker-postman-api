# Environment Configuration

## Overview

The Restful Booker Postman API automation suite uses a dedicated Postman environment to manage reusable configuration and runtime test data.

The environment separates static configuration from dynamically generated values, making the collection reusable across multiple executions.

## Environment

**Environment Name:** `Restful Booker - QA`

**Base URL:**

```text
https://restful-booker.herokuapp.com
```

## Environment Variables

| Variable          | Type    | Initial Value                          | Purpose                                                   |
| ----------------- | ------- | -------------------------------------- | --------------------------------------------------------- |
| `baseUrl`         | Static  | `https://restful-booker.herokuapp.com` | Base URL for API requests                                 |
| `username`        | Static  | `admin`                                | Authentication username                                   |
| `password`        | Static  | `password123`                          | Authentication password                                   |
| `token`           | Runtime | Blank                                  | Stores the authentication token generated by Create Token |
| `bookingid`       | Runtime | Blank                                  | Stores the booking ID generated by Create Booking         |
| `createFirstname` | Static  | `Arindam`                              | First name used when creating a booking                   |
| `createLastname`  | Static  | `Chowdhury`                            | Last name used when creating a booking                    |
| `updateFirstname` | Static  | `Avishka`                              | First name used when updating a booking                   |

## Static vs Runtime Variables

### Static Variables

The following variables are configured before execution:

* `baseUrl`
* `username`
* `password`
* `createFirstname`
* `createLastname`
* `updateFirstname`

These values provide reusable configuration and test data.

### Runtime Variables

The following variables are generated or updated during execution:

* `token`
* `bookingid`

The runtime values should initially be blank.

### Token Lifecycle

The `Create Token` request authenticates against the API and extracts the returned token.

The token is stored dynamically in:

```text
{{token}}
```

Authenticated requests then use:

```text
Cookie: token={{token}}
```

### Booking ID Lifecycle

The `Create Booking` request extracts the generated booking ID from the response.

The ID is stored dynamically in:

```text
{{bookingid}}
```

The main CRUD flow uses this value for:

* Get Booking — Verify Creation
* Update Booking
* Get Booking — Verify Update
* Delete Booking
* Verify Booking Deleted

Negative and boundary scenarios that create independent bookings do not overwrite the main `bookingid`.

## Environment Setup

1. Open Postman.
2. Import the environment file from:

```text
environments/Restful-Booker-QA.postman_environment.json
```

3. Select the `Restful Booker - QA` environment.
4. Verify that the static variables contain the expected values.
5. Confirm that `token` is blank.
6. Confirm that `bookingid` is blank.
7. Run `Create Token`.
8. Verify that `token` is populated.
9. Run `Create Booking`.
10. Verify that `bookingid` is populated.

## Variable Usage

| Variable          | Used By                              |
| ----------------- | ------------------------------------ |
| `baseUrl`         | All API requests                     |
| `username`        | Create Token                         |
| `password`        | Create Token                         |
| `token`           | Authenticated Update/Delete requests |
| `bookingid`       | Main CRUD verification flow          |
| `createFirstname` | Create Booking                       |
| `createLastname`  | Create Booking                       |
| `updateFirstname` | Update Booking                       |

## Runtime Variable Management

Runtime values are intentionally not stored as permanent test data.

Before exporting the environment for GitHub:

```text
token = ""
bookingid = ""
```

This ensures that the exported environment does not contain stale runtime values.

## Security Considerations

This project uses the publicly documented credentials for the Restful Booker demo API.

No personal credentials, production credentials, API keys, or sensitive secrets should be committed to the repository.

For real-world projects, sensitive values should be managed through secure environment variables or a dedicated secrets-management solution rather than committed to source control.
